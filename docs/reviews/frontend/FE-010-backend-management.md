# FE-010 后台管理页面 Review 总览

## 1. 范围

本批按六个子域审查：

- 用户：用户、班级、学生、用户查询与成员选择
- 权限：权限资源树、菜单资源编辑、图标/父级选择
- 角色：角色 CRUD、角色权限、角色成员
- 题目：题目编辑、题单、目录、标签、题解及题目测试数据入口
- 竞赛：竞赛/作业、参与人、迟交、题目统计、用户统计、成绩详情
- 系统：公告、文件、缓存、判题提交日志、判题测试用例日志

Review 初次完成后，本批已执行第一轮修复。修复集中在请求一致性、权限边界、表单提交和服务端分页过滤，没有改变已有端口、路由名称或数据库字段。

## 5. 本轮已执行

### 请求与表单一致性

- 用户、班级、角色、角色成员、文件、公告、判题记录和缓存读取增加请求快照/请求代际保护，旧响应不能覆盖当前筛选条件。
- 表格刷新后同步清理 Element Plus 的真实选中状态，移除 `reserve-selection` 与本地数组不同步的问题。
- 用户、班级、角色、权限资源的新增/编辑不再把可变 `reactive` 对象交给延迟 debounce；点击保存时生成快照并由页面统一控制 loading、成功和失败状态。
- 学生管理改为响应式读取路由班级 ID，批量移除与单行移除共用操作锁；题单排序删除、分数保存增加重复操作保护。

### 权限与数据安全

- 角色资源授权改为等待所有增删授权请求并汇总结果；部分失败不会再提示“权限已更新”，下次打开会重新读取资源树和角色授权。
- 角色权限资源树每次打开刷新，避免菜单新增后继续使用旧树；角色不存在或角色详情加载失败时禁止成员授权操作。
- 菜单资源编辑时，父级选择排除当前节点及全部子孙节点，避免产生树循环；切换菜单类型会清理不适用的图标、路由、组件和权限字段。
- 缓存类型列表也受 `content:cache:list` 后端权限保护，缓存键和值读取继续由同一权限校验。
- 判题提交/测试用例日志的刷新、查询和详情入口补齐权限指令，详情请求失败时不再永久显示骨架屏。

### 服务端过滤与后台体验

- 公告支持标题、重要级别服务端过滤，文件支持文件名/路径/MD5/类型服务端过滤，分页总数与可见列表保持一致。
- 文件管理下载入口沿用文件读取权限指令；普通资料下载仍保留原有公开读取接口，不影响前台资料使用。
- 角色缓存刷新失败继续向页面抛出失败结果，避免 API 吞掉错误后页面误以为刷新成功。

## 6. 本轮验证

- `oj-vue`: `pnpm run type-check` 通过。
- `oj-vue`: `pnpm run build-only` 通过；仅保留既有动态导入和大 chunk 警告。

## 7. 尚未在本轮扩大范围的事项

- 竞赛/作业后台大量页面的共享壳组件仍需后续抽取，当前先保持既有线上布局，避免一次性替换造成回归。
- 移动端操作列仍有少数页面采用隐藏 fixed-right 的旧策略，后续应统一改为横向滚动或行操作菜单。
- 管理后台通用 `usePagedTable`、`AdminDialogForm` 和日志抽屉尚未抽成独立组件，本轮先用局部请求代际保护止住实际 bug。

## 2. 总体结论

后台页面已经从早期的零散表单演进成了“统一壳 + 面板 + 表格 + 权限指令”的形态，暗色变量和权限字符串也有一定复用。但目前的主要问题不是单个 CSS 值，而是页面边界没有统一：

1. 多数列表把服务端分页和前端当前页过滤混在一起，`total` 与实际可见行不一致。
2. 页面普遍用模块级响应式对象配合 lodash `debounce`，关闭弹窗、切换路由或快速连续操作时，延迟请求仍可能读取已经被 reset 的对象。
3. 列表请求没有统一的请求代际/取消机制，旧响应可以覆盖新筛选、切换角色、切换竞赛或切换缓存键后的状态。
4. 权限显示大多做到了按钮级 `v-has`，但“查看页面”“打开弹窗”“读取敏感数据”和“执行写操作”没有形成一致的权限模型。
5. `ContestSubPageShell` 被竞赛、系统、权限等多个领域共享，名字和样式职责已经越界；各页面又复制 `.panel-heading`、`.filter-panel`、`.status-pill`、`.dialog-intro` 等样式，导致修改一个页面很容易影响另一个页面，或出现视觉不一致。
6. 小屏处理经常直接隐藏 `.el-table__fixed-right`，用户会失去操作入口；更合理的是操作列进入行菜单、提供横向滚动或使用详情抽屉。

## 3. 建议的修复顺序

### 第一阶段：先堵功能和权限风险

- 收敛所有列表的查询模型：服务端过滤/分页，前端只做展示级派生数据。
- 抽取可取消、带 request id 的列表请求 composable，旧请求不能写回。
- 取消“把 reactive form 传进 debounce”的模式，debounce 调用时传入不可变快照，并在卸载/关闭时 cancel。
- 权限入口、读取、写入分别定义 permission key；敏感的文件下载、缓存值、判题日志详情不能只靠路由可见性。
- 修复权限树父子循环、角色权限保存竞态、竞赛子页参数快照等高风险问题。

### 第二阶段：抽取共享基础组件

- `AdminPageShell`：页面标题、返回、操作区、统计条。
- `AdminFilterPanel`：筛选项、搜索/重置、折叠行为。
- `AdminTablePanel`：表格容器、空状态、分页、选择状态。
- `AdminDialogForm`：弹窗 loading、取消/关闭 reset、表单校验和提交状态。
- `usePagedTable`：查询快照、request id、取消、分页、选择清理。
- `useDebouncedAction`：只负责防抖，不持有外部可变对象，不吞错误。
- `AdminStatusPill`、`AdminUserCell`、`AdminIdCell`、`AdminLogDrawer`。

### 第三阶段：统一视觉和响应式

- 用 CSS 变量替换各页面硬编码的紫/蓝/黄颜色。
- 不再用“移动端隐藏固定操作列”作为响应式策略。
- 统一面板内边距、表格最小宽度、抽屉/弹窗最大高度和滚动归属。
- 统一暗色模式下的 `color-mix`、代码/日志背景、边框对比度和 hover 状态。
