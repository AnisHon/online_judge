# OJ 测试用例文件人工对账

用例文件替换会先写入同 bucket 的新 UUID 路径，再由数据库事务切换
`oj_problem_case.input/output`。替换或删除用例时，旧 MinIO 对象不会在请求内删除：
练习判题任务可能已经读取了旧路径。应用也不会自动扫描或批量清理对象。

只有需要回收空间时才执行人工对账：

1. 先备份 MinIO bucket 和 `oj_problem_case` 表，并暂停相关题目的新提交。
2. 等待这些题目所有 `submit_log.status` 处于 QUEUE、COMPILING 或 RUNNING 的记录结束；
   不要仅按“比赛已结束”判断，普通练习提交也必须纳入。
3. 导出所有未删除用例当前引用的 `input`、`output` 路径，与该 bucket 的对象清单逐项比较。
4. 只把“对象存在但不被任何当前用例行引用”的路径列为候选；先人工核对 UUID 路径、题目和用例 ID，
   再由运维人员逐个删除。不要使用目录级通配删除，也不要把数据库中仍引用的路径当作垃圾。
5. 记录对象路径、确认人、对账时间和删除结果。无法确认归属的对象保留并升级处理。

如果事务失败后的临时对象清理也失败，服务只记录不含用户内容的清理告警；该对象按同一对账流程处理。
